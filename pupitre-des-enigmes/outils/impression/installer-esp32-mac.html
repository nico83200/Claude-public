Installer le programme sur l'ESP32 depuis un Mac

La carte ESP-32S du pupitre (ESP32-WROOM-32, prise USB-C, puce USB CH340), programmée depuis macOS : sans rien installer avec un navigateur, ou avec PlatformIO pour modifier le code.

Trois chemins, selon ce que vous voulez faire

A · Le navigateurInstaller le programme déjà compilé, sans rien installer sur le Mac. Le plus simple : 10 minutes.
B · VS Code + PlatformIOPour modifier le code et le renvoyer dans l'ESP32 d'un clic. 30 minutes la première fois.
C · Le TerminalLa même chose que B, en ligne de commande, pour ceux qui préfèrent.

Une fois le programme installé une première fois par le câble, les mises à jour peuvent passer par le Wi-Fi du pupitre (chapitre 6) : plus besoin d'ouvrir la boîte.

1. Le matériel

Il vous fautPourquoi, et le piège à éviter
Un câble USB-A → USB-C qui transporte les donnéesBeaucoup de câbles ne font que charger : la carte s'allume, mais le Mac ne la voit pas. Avec un câble USB-C → USB-C, certaines de ces cartes ne sont pas reconnues du tout.
Un adaptateur ou hub USB-C → USB-ALes Mac récents n'ont que des prises USB-C (Thunderbolt). Branchez-y l'adaptateur, puis le câble USB-A → USB-C.
Google Chrome ou Microsoft EdgePour le chemin A : Safari et Firefox ne savent pas parler au port USB.
macOS 11 (Big Sur) ou plus récentLes Mac Intel et Apple (M1 à M4) conviennent tous les deux.
Avant de brancher

Si l'ESP32 est déjà câblé dans le pupitre, débranchez le fil de la GPIO 2 (TX vers le DFPlayer du casque) le temps de la programmation : la GPIO 2 doit être libre quand la carte démarre en mode programmation. L'alimentation du pupitre peut rester débranchée : le câble USB alimente la carte.

2. Le Mac voit-il la carte ?

La carte parle au Mac par une petite puce, la CH340. Les versions récentes de macOS la reconnaissent souvent sans rien installer. Vérifions-le.

  1. Branchez la carte. Sa petite LED rouge s'allume.
  2. Ouvrez le Terminal : ⌘ + Espace, tapez Terminal, Entrée.
  3. Tapez cette commande, puis Entrée :
    ls /dev/cu.*
    Vous devez voir une ligne comme /dev/cu.usbserial-1420 ou /dev/cu.wchusbserial1420 : c'est la carte. Débranchez-la et relancez la commande : la ligne disparaît. C'est bon, passez au chapitre 3.
  4. Si seules des lignes comme /dev/cu.Bluetooth-Incoming-Port apparaissent, essayez d'abord un autre câble (c'est la cause la plus fréquente), puis installez le pilote ci-dessous.

Installer le pilote CH34x (seulement si besoin)

  1. Sur le site du fabricant de la puce, wch-ic.com, cherchez CH34XSER_MAC (le pilote « CH34x » pour macOS) et téléchargez-le.
  2. Ouvrez le fichier téléchargé et suivez l'installation. Sur macOS 11 et plus, il s'installe comme une application : lancez-la et cliquez sur Install.
  3. macOS bloque l'extension : ouvrez Réglages Système → Confidentialité et sécurité, descendez jusqu'au message sur le logiciel du développeur de la puce (WCH, « Nanjing Qinheng Microelectronics ») et cliquez sur Autoriser.
  4. Redémarrez le Mac, rebranchez la carte et refaites ls /dev/cu.* : une ligne /dev/cu.wchusbserial… apparaît.

3. Chemin A : le navigateur, sans rien installer

Le programme déjà compilé est dans le projet : pupitre-des-enigmes/firmware/binaires/pupitre-complet.bin.

Récupérer le fichier

  1. Ouvrez le projet sur GitHub, dans la branche qui contient la dernière version du pupitre.
  2. Allez dans pupitre-des-enigmes → firmware → binaires, cliquez sur pupitre-complet.bin, puis sur le bouton de téléchargement (Download raw file, la flèche vers le bas). Le fichier arrive dans Téléchargements.

Le mettre dans l'ESP32

  1. Dans Chrome, ouvrez https://espressif.github.io/esptool-js/ : l'outil officiel d'Espressif, le fabricant de l'ESP32.
  2. Laissez Baudrate à 115200 (ou 460800 pour aller plus vite) et cliquez sur Connect.
  3. Chrome affiche la liste des ports : choisissez la carte (USB Serial, USB2.0-Serial ou wchusbserial), puis Connexion. Si la connexion échoue, recommencez en maintenant le bouton BOOT de la carte enfoncé pendant « Connecting… », puis relâchez-le.
  4. Dans le tableau qui apparaît, Flash Address : écrivez 0x0. La page propose souvent 0x1000 par défaut : remplacez-le, sinon la carte redémarre en boucle en affichant « invalid header: 0xffffffff ». Choisissez le fichier pupitre-complet.bin.
  5. Cliquez sur Program. La barre avance pendant une minute environ. Attendez le message de fin (Leaving…).
  6. Cliquez sur Disconnect, débranchez, rebranchez : le logo du Pupitre s'affiche sur l'écran (si l'écran est câblé). Rebranchez le fil de la GPIO 2.
Bon à savoir

pupitre-complet.bin contient tout (démarrage, table des partitions, programme) : il s'écrit toujours à l'adresse 0x0. L'autre fichier, pupitre-mise-a-jour.bin, ne sert qu'aux mises à jour par le Wi-Fi (chapitre 6) : ne l'envoyez jamais à 0x0.

4. Chemin B : VS Code et PlatformIO, pour modifier le code

Installer les outils (une seule fois)

  1. Les outils de développement d'Apple (Python, Git) : dans le Terminal,
    xcode-select --install
    Une fenêtre propose l'installation : acceptez (quelques minutes). Si la commande répond qu'ils sont déjà installés, tout va bien.
  2. Visual Studio Code : téléchargez-le sur code.visualstudio.com (version macOS, « Universal »), décompressez, et glissez Visual Studio Code dans le dossier Applications. Ouvrez-le.
  3. PlatformIO : dans VS Code, cliquez sur l'icône des Extensions (les quatre carrés, à gauche), cherchez PlatformIO IDE, cliquez sur Install. Patientez : PlatformIO télécharge ses outils (quelques minutes), puis demande de recharger la fenêtre.

Récupérer le code

  1. Sur GitHub, dans la branche du projet, bouton vert Code → Download ZIP. Décompressez le ZIP (double-clic), par exemple dans Documents.
    Ou, dans le Terminal :
    cd ~/Documents git clone https://github.com/nico83200/Claude-public.git cd Claude-public git checkout # le nom de la branche du projet
  2. Dans VS Code : Fichier → Ouvrir le dossier… et choisissez le dossier pupitre-des-enigmes/firmware (celui qui contient platformio.ini), pas le dossier du dessus.

Compiler et téléverser

  1. En bas de la fenêtre, la barre bleue de PlatformIO apparaît. Cliquez sur la coche ✓ (Build). La première fois, PlatformIO télécharge l'ESP32 et les bibliothèques (écran, RFID, audio, LED, JSON) : comptez quelques minutes. Le message SUCCESS termine la compilation.
  2. Branchez la carte (fil de la GPIO 2 débranché). Cliquez sur la flèche → (Upload). PlatformIO trouve le port tout seul.
  3. Si « Connecting…… » s'éternise : maintenez le bouton BOOT enfoncé jusqu'à ce que les pourcentages s'affichent.
  4. Cliquez sur la prise (Serial Monitor) pour voir le journal du pupitre : lecteurs RFID détectés, capteurs présents, cartes posées, erreurs. Pour fermer le moniteur : Ctrl + C dans son terminal.
Choisir le port à la main

Si PlatformIO prend le mauvais port (un casque Bluetooth, par exemple), ajoutez dans platformio.ini, sous [env:pupitre], la ligne upload_port = /dev/cu.usbserial-1420 (le nom vu au chapitre 2).

5. Chemin C : tout dans le Terminal

# une seule fois : PlatformIO (avec Homebrew, ou avec pip) brew install platformio # si Homebrew est installé python3 -m pip install --user platformio # sinon # ensuite, à chaque fois cd ~/Documents/Claude-public/pupitre-des-enigmes/firmware pio run # compiler pio run -t upload # téléverser par le câble USB pio device monitor # le journal série (115 200 bauds) ; Ctrl+C pour quitter

Avec pip, si le Terminal répond « command not found: pio », utilisez python3 -m platformio à la place de pio.

6. Les mises à jour suivantes, par le Wi-Fi

Après la première installation par le câble, plus besoin d'ouvrir la boîte : le pupitre se met à jour par son propre Wi-Fi.

  1. Allumez le pupitre. Sur le Mac, menu Wi-Fi : rejoignez le réseau Pupitre-des-Enigmes (mot de passe enigmes123).
  2. Sans PlatformIO : dans un navigateur, ouvrez http://192.168.4.1, tapez le code d'accès (1234 au départ, ou celui que vous avez choisi), onglet Mise à jour, et envoyez le fichier firmware/binaires/pupitre-mise-a-jour.bin (ou, après une compilation, firmware/.pio/build/pupitre/firmware.bin).
  3. Avec PlatformIO : choisissez l'environnement pupitre-wifi dans la barre bleue (ou pio run -e pupitre-wifi -t upload dans le Terminal).
  4. Le pupitre redémarre tout seul. Ne coupez pas le courant pendant l'envoi : en cas d'échec, l'ancien programme reste en place.
Penser à revenir

Pendant ce temps, le Mac n'a plus Internet. Une fois la mise à jour faite, rejoignez de nouveau votre réseau Wi-Fi habituel.

7. Si ça coince

Le symptômeLa solution
Aucun port /dev/cu.usbserial… ou wchusbserial…Changez de câble (il doit transporter les données) et d'adaptateur ; essayez une autre prise du Mac. Puis installez le pilote CH34x (chapitre 2) et redémarrez.
Le pilote est installé mais rien n'apparaîtRéglages Système → Confidentialité et sécurité : autorisez l'extension de WCH (Nanjing Qinheng), puis redémarrez.
Failed to connect to ESP32 · Timed out waiting for packet headerMaintenez BOOT pendant « Connecting… ». Débranchez le fil de la GPIO 2. Essayez une vitesse plus basse (115200 dans esptool-js).
Resource busy · Permission denied sur le portUn autre programme tient le port : fermez le moniteur série, l'IDE Arduino, un autre onglet esptool-js. Débranchez, rebranchez.
Chrome ne propose aucun portVérifiez que vous êtes bien dans Chrome ou Edge (pas Safari). Autorisez Chrome si macOS le demande.
Le journal affiche des caractères illisiblesRéglez le moniteur sur 115 200 bauds.
La carte redémarre en boucle après l'installationRéinstallez pupitre-complet.bin à 0x0 (pas le fichier de mise à jour). Débranchez l'écran et les modules pour tester la carte seule.
L'écran reste noir, mais le journal défileLe programme tourne : vérifiez le câblage de l'écran (voir la notice de montage et le plan de câblage).

8. Et après ?

  1. Préparez la carte micro-SD de l'écran : copiez le contenu de cartes-sd/carte-sd-ecran.zip à sa racine (formatée en FAT32). Sur Mac : Utilitaire de disque → Effacer → format MS-DOS (FAT).
  2. Préparez les deux cartes des lecteurs audio (voir cartes-sd/LISEZMOI.md). Sur Mac, après la copie, lancez dot_clean /Volumes/NOM_DE_LA_CARTE dans le Terminal pour effacer les fichiers cachés « ._ » que macOS ajoute, puis éjectez la carte.
  3. Allumez le pupitre, appuyez sur la molette : Préparer le pupitre, et enregistrez les cartes de chaque monde.
  4. Jouez votre première partie avec Panique au Muséum, le tutoriel.
